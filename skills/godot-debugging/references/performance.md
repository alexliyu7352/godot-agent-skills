# 性能测量与回归

## 测量条件
记录引擎/构建、硬件/渲染后端、分辨率、NPC/数据规模、输入序列和采样窗口。冷加载、稳定运行和退出分别观察。headless 数据吞吐与实际渲染帧率不能互相替代。

先看帧时间及卡顿分布，不仅平均 FPS。Profiler 的函数耗时与调用次数、Monitors 的对象/节点增长、内存和渲染统计帮助区分 CPU、GPU、I/O 与对象生命周期问题。具体指标名称随版本核对。

## 常见排查方向
高频节点查找、每帧大量临时对象、重复数据计算、同步加载、无必要信号广播、全世界逐帧更新、UI 全量重建。它们是候选热点，不是见到就修改。缓存需要明确失效条件；静态优化可能引入过期数据显示。

使用批处理、低层 Server API、C# 或原生扩展不自动改变算法复杂度。先估计工作量和瓶颈，再实现最小修改，在同条件下复测；不要写无证据的固定倍数收益。

## 长时间与规模
人物从 10 到 1000 时测曲线和峰值，考虑你项目的真实规模。检测多次进入离开场所后对象/内存持续增长。大步时间推进和存档加载也应测延迟，不能只优化当前画面。

一个资源加载缓存优化可能让首次加载不变、后续变快；报告二者，不能只挑有利样本。若改动影响模拟精度、随机顺序或玩法结算，先确认设计允许，而不是把行为改变包装成优化。

## 验收
保存前后测量条件与摘要，回归验证原行为。只优化已定位热点；无相关证据就保留维护性更好的实现。需要长期监控或性能平台属于另一个任务，不由本技能自动引入。
