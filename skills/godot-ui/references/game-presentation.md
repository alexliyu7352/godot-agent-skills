# 游戏化呈现：场所、人物与界面的连续体验

适用于场景主导的 RPG/生活模拟交互。它不是强制所有类型游戏场景化的模板。用玩家当前意图组织界面，不按开发模块名称组织一个“系统后台”。

## 同一场所的进入、交谈和返回
进入时，画面先建立空间、当前人物及可操作物件；鼠标悬停、聚焦或项目已有提示方式揭示可交互性，不必把每个对象永久框成按钮。交谈时，在场者、称谓和话题相对应；结束后关闭临时层并恢复场所焦点，不销毁房间后返回一张功能列表。

若 NPC 日程改变，对象可用性、可见提示与真实状态同步。没有可领取任务时可以闲谈、说明原因或退出，不需要伪造任务填满选项。交易可用高效清单，但应从当前商人进入；关闭后仍在店铺。设置、存档选择、地图、关系图无需强行放在某个人物身上。

## 构图与信息层级
画面主体、当前行动和周边状态要有阅读顺序。常驻 HUD 只保留当前需要的信息；交互说明出现在目标附近或固定且稳定的提示区。不要同时有顶部菜单、侧栏、中央卡片和底部重复入口。不是“禁止按钮”，而是不让按钮体系取代世界。

对白层应留出人物脸、手和动作物件的空间。背景复杂时用有限范围的明暗支撑文字，不把整幅画面涂暗；文字在实际游戏尺寸可读，不能靠细小书法字制造“高级”。选项需要清楚的选中、禁用、焦点、等待状态，不仅换颜色。中文长句先安排正文宽度与行距，再决定是否需要滚动或分页。

## 反馈而不是效果堆叠
根据人物语气改变表情/视线或有限姿态，避免所有人同频缩放的“呼吸动画”。确认、拒绝与处理中反馈有不同语义。事务成功后才展示成功；重复点击不能重复领取。返回/取消优先响应，不因补间尚未完成而吞键；动效在相关节点释放时停止。

## 原生实现与输入路径
Label/RichTextLabel 承担变化文本，按钮或热点承担输入，底图仅承担绘景。全屏概念图上烧录三个选项，再覆盖透明点击框，不是原生对话 UI。带有原图 UI 的候选需要先获得干净资产或做明确且有记录的裁切，不能用新面板遮住旧字后称为完成。

热点和视觉对象共享坐标转换、裁切与状态。鼠标悬停提示不能遮住另一个目标；面板打开时阻止背景误点，关闭后恢复原焦点。按项目已经支持的输入方式检查同一对象；支持键盘/手柄时提供对应焦点路径，不擅自为局部修改扩展新的设备支持。引用是否存在和函数能调用不证明玩家确实走过这条路径。

## 范围判定
改一个选项间距：目标状态原生显示、焦点和相关命中范围足够。新做一间商铺：检查进入、面对商人、交易面板和返回，不必先做完整经济模拟。公共 HUD 或输入策略修改才扩展到受影响的其他场所。
