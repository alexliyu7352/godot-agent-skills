# 成套资产：从视觉种子到 Godot

用于新背景、人物、图标家族或资产修订。局部文字/间距不需要本流程。使用实际可用工具，既不强制外部收费服务，也不把缺工具当成可以用色块交付成品的理由。

## 在生成前区分两种文件
**目标合成图**允许展示理想人物、房间和 UI 的关系，但不是可编辑引擎资产。**运行资产**必须按实际变化需求拆分：会消失/移动的人物、改变的门、遮挡前景、文字和按钮，不应永久烘焙进同一图。

固定绘景可以作为合理的游戏表现方法；关键对象永远静止时不必强制拆成几十层。若暂时使用整幅人物绘景加热点，只称为静态场景交互样例，不声称已有独立 NPC 动画、可换装立绘或完整世界模拟。

## 资产清单的最低字段
| 字段 | 用途 |
|---|---|
| id / file / role | 哪个文件承担什么游戏职责 |
| dimensions / display_scale | 输出尺寸与游戏内尺度，不只看原图清晰度 |
| alpha / padding / pivot | 是否需要透明、轮廓余量、接地点或锚点 |
| invariants | 身份、镜头、光向、色彩、材质中哪些不得漂移 |
| source / edits / status | 来源或生成记录、后处理、候选/已验收状态 |
| runtime_state | 哪些状态会替换/隐藏，哪个节点负责 |

记录可用的来源与许可事实，不臆造生成素材独占权。字体通常引用项目自己的合法文件或系统依赖；本技能包不分发字体。许可证和生成出处放旁边，不要求每次开发读取全部法律文本。

## 图像工具任务的具体描述
每次明确用途、对象及姿态、视角/朝向、材质/明暗、输出尺寸与透明要求，并区分“改变什么”和“保持什么”。人物变体复用同一身份参考；不要每张独立描述一次“古代官员”。生产资产排除 UI 文字、重复人物和展示边框；不把要求“透明背景”的一句提示当成已经有 alpha。

## 确定性后处理
核对实际尺寸和 alpha：RGB 图或不透明棋盘格不是透明图；半透明边缘需分别置于浅、深和实际背景检查。以脚底/坐席/握持点对齐变体，不仅对齐画布中心。裁切避免切手脚与阴影；删掉背景后应检查重建缺口，不能用模糊补丁藏在角色周围。生成帧表不是可靠网格，切片前检查每格位置、身份与体积。

绘景与人物尽量在目标显示尺度检查清晰度。可以输出有记录的有损运行副本，但原视觉种子要保留；不要为便于上传而悄悄把正式资产缩成缩略图。修改必须能从原图和参数复现。

## Godot 导入与绑定
按实际尺度选择过滤与压缩，不把像素画过滤策略套给绘画背景。贴图尺寸、色彩空间、缩放方式和 mipmap 需求随项目确定，不能以默认值等同验收。NinePatchRect/StyleBoxTexture 仅拉伸适合拉伸的边框和中心，文字仍用 Label/RichTextLabel；人物、脸、道具不随窗口非等比拉伸。

TextureRect 的保持比例覆盖模式会裁切；若人物热点跟着底图，热点也必须使用同一缩放和偏移，不能自己按窗口百分比摆一次。装饰 Control 设为忽略鼠标，交互由单独的状态/输入节点处理。实际小版本 API 以项目为准。

[TextureRect](https://docs.godotengine.org/en/4.6/classes/class_texturerect.html) 与 [Control](https://docs.godotengine.org/en/4.6/classes/class_control.html) 是本次核对的 4.6 API，不是升级项目要求。

## 上屏后再决定是否接受
在同一引擎画面一起看背景、人物、道具与 HUD，检查比例、光向、轮廓、色彩职责、点击区域和相关状态。漂亮单图若与邻居不属于同一风格应退回修改。若只有合成概念图，就交代下一阶段缺哪些实际文件，不伪称已完成 Godot 集成。
