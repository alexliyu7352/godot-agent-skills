# Godot 存档与恢复

## 适用边界
处理玩家存档与世界恢复，不处理编辑器保存场景。保留已有可靠存档格式和测试框架；不要仅为统一示例而迁移格式。

## 先读什么
明确权威状态在哪里、何时允许保存、有哪些版本、实际数据量及平台文件语义。当前场景的 saveable 分组只是可能的数据来源，不天然涵盖未加载城镇和人物。

## 工作方法
1. 在明确的结算边界获取一致快照；使用稳定 ID，记录格式版本及必要的内容版本、时间和随机状态。派生缓存优先重建，不保存场景对象地址。
2. 读取分阶段进行：读取/解析 → 拒绝不支持版本 → 逐版本迁移 → 校验 → 暂存恢复对象 → 一次提交。失败时保持当前世界不变；不能先改玩家再发现世界加载失败。
3. 新于程序支持版本的存档直接拒绝并保留原文件；不能把版本字段改小。迁移只能在副本上执行，经完整校验后使用。
4. 写入采用同目录临时文件、检查每步 I/O、关闭后按平台能力替换。保留可验证备份/恢复策略；flush 或 rename 单独不等于跨平台断电安全。
5. 恢复失败必须向调用者返回失败；缺失关键实体或资源不能记录错误后继续返回成功。可选缺失的容错规则必须来自项目契约。
6. 使用备份前校验并记录恢复来源；失败或降级恢复后避免自动保存覆盖原始问题文件。外部存档是数据，不信任它给出的脚本/资源加载路径。

## 验证与交付
按变更选检查：格式/迁移改动验证受支持版本、未来版本、畸形数据；写入路径改动注入相关 I/O 失败；恢复提交改动验证部分失败不污染旧世界；快照或对象关系改动加入退出重启和离屏一致性。局部错误提示改动仅验证对应分支，不默认运行整套矩阵。
