# 快照、版本迁移与恢复提交

## 权威快照
列出必须恢复的状态及所有者，包括离屏人物、任务、经济、时间和正在进行的行动。当前节点分组只覆盖已加载实例时，必须说明其余世界状态从何处获得。不要保存 Node/Object 地址；用稳定 ID 重建引用。

快照在已定义的结算边界获取。若序列化异步执行，要保证数据副本不在序列化过程中被其他动作修改。不要在没有性能证据时引入复杂后台写入架构。

## 加载管线
1. 从选定路径读取原始字节，检查 I/O 和大小限制，解析数据结构。
2. 验证版本字段类型及支持范围：大于当前支持版本则拒绝，不修改原数据/文件。
3. 在候选副本逐步执行 vN→vN+1 迁移；每一步明确输入、输出和验证。缺少迁移链则失败，不能只改版本号。
4. 校验 ID 唯一、引用存在、数值范围、任务状态和跨系统不变量。
5. 暂存恢复结果/新世界对象。任何关键恢复失败都返回明确失败。
6. 全部准备就绪后切换到新状态并更新表现。旧世界在提交前保持有效；提交中可能失败时需已有恢复/回滚策略。

Godot 中实例化场景可能执行初始化脚本，因此暂存并非天然无副作用。把影响权威世界的注册/通知放在可控制的提交边界，或在测试中确认旧结构不会被候选加载污染。

## 迁移的幂等与边界
迁移方法只接受其声明的输入版本并产生目标版本，重复加载同一旧档应得到一致结果。fixture 包括每个支持历史版本、畸形版本、缺字段、重复实体与未来版本。当前版本是 2 而存档版本为 5 时，拒绝并保留字节，不伪装成 2。

JSON 数值和引擎 Variant 不完全等价。稳定 ID 宜使用字符串；枚举、向量和高精度整数要有明确编码/校验，不能假设类型自动恢复。加载不受信数据时禁用任意对象/脚本反序列化，资源路径使用可控定义映射。

## 报告成功的条件
所有必需状态恢复并满足不变量才算加载成功。日志中“缺失场景，已跳过”不能与成功返回共存，除非该场景按设计明确可选且降级结果被记录。区分成功、降级恢复、拒绝版本、损坏与 I/O 失败。
