# 对话数据校验与内容维护

## 构建/导入时检查
节点/选项/行 ID 唯一，跳转目标存在，入口和要求可达的节点可达，必需的说话人/翻译 ID/效果类型可解析。区分可选资源缺失与阻断主线的缺失，不能统一静默跳过。

静态可达性不能证明带世界条件的分支总是可达。条件系统需要代表性状态组合 fixture；复杂表达式无法穷尽时记录已覆盖与剩余风险，不宣称“图无环所以对话不会卡住”。有意的交互循环允许存在；无等待的自动循环需预算或诊断。

## 内容与代码边界
显示文本和外部导入内容不能自动变成任意可执行代码。项目已审核的对话脚本、插件表达式与注册命令仍可按原能力使用，不把它们一概禁用或另写解析器。项目适配层校验命令参数、状态身份和业务入口；只有实际支持 mod/外部脚本时再按信任边界增加隔离，不扩展成完整安全平台。

ID 用于定位和持久引用，显示文本可翻译和改写。重新排序选项不应让旧选择指向另一个动作。删除/改名已进入存档的节点时依据存档契约迁移或明确中止旧会话。

## 人物与场景契约
确认发布者、交互入口、条件与效果绑定到同一份人物/任务身份。官署中的办事人员必须真实可交谈，不是只给一个系统页面放头像。此原则来自项目设计时遵循项目设计；技能本身不限定所有游戏都必须采用同一表现方式。

## 审查输出
按影响报告：会卡死或重复奖励是行为缺陷；缺少必需内容是集成缺陷；命名/排版是维护建议。不要将所有静态警告都当成游戏不可交付，也不能用视觉良好掩盖状态错误。
