# 对话状态契约

## 先接现有运行器，不重写对话框架
先读取工程实际使用的插件版本、一个能工作的对话文件/场景以及项目封装。Dialogue Manager、Dialogic 或自研运行器的 API 不互换；缺版本信息时查本地插件代码，不按别的库的函数名猜。只改文案/样式时不要调整运行器和存档模型。

沿现有接口查清五个接点：开始时传入哪个人物/上下文；一行何时显示完且何时等待确认；有效选项怎样映射回原 ID；效果由谁提交；结束/取消如何恢复场所。优先保留现成编辑器、导入器、翻译和运行器；只有接口确有差异才做小型适配。

运行器内部返回节点索引时，在显示过滤/重排后保存“显示项→真实选择身份”的映射，不能把第2个可见选项当成原列表第2项。显示一行与继续推进分开，打字机播放结束不自动批准业务动作。项目运行器若已有明确自动播放规则则沿用，不反向禁止自动台词。

条件从唯一权威状态读取；内建对话变量可以管理会话表现，但库存/任务不能同时在插件与游戏层各存一份互相覆盖。插件命令调用项目已有业务入口，完成结算再刷新话题，而不是在文本里复制交易公式。

## 运行时状态
沿用项目的表现方式，但明确：当前节点、有效选项、是否等待输入、是否正在提交效果、是否结束/取消。UI 根据运行器的有效状态显示；不要一个地方按过滤后选项判断，另一个地方仍按原始列表判断。

## 零选项必须有行为
先区分没有选项的普通台词与“定义了选项但全部条件不满足”。后者按设计执行 fallback 台词/节点、返回或结束。允许玩家取消可以是兜底，但不能替代设计要求必须可继续的主线。

边界 fixture：两个选项分别要求声望达标和携带任务物品；玩家两项都不满足。期望有明确反馈与退出/返回路径，不能出现没有按钮且 continue 被拒绝的状态。

## 提交时条件与副作用
显示菜单时得到的结果可能过期。提交时重新验证人物、任务阶段、库存和场景状态；不满足则刷新选项或给出明确反馈。不能先发奖励再检查任务是否还能提交。

区分节点进入、文字播放、选择确认与效果提交。快进文字不提交两次；重新打开不再次发放一次性奖励。成功提交后才发对外状态变更通知。动作身份与持久任务完成状态要能在保存恢复后保持语义。

## 取消、离开与重入
明确取消是否回滚尚未提交的动作；已提交的动作不能仅因动画取消而偷偷撤销。NPC 消失、场所切换、人物死亡等使上下文失效时停止旧对话实例，防止 await 后写回新会话。

用实例世代/会话标识丢弃过期回调，或使用已有取消机制；不要额外建立网络式会话系统解决一个本地 UI 问题。

## 与改动对应的验收
选项过滤/排序修改检查正常、零选项和真实选择身份；效果提交修改检查条件过期、重复确认与一次性结果；生命周期修改检查退出、NPC 卸载和旧回调；自动推进修改检查循环/等待；持久进度修改才追加重新启动恢复。局部排版不因此触发全部逻辑回归。

每个选定用例写明最终节点与相关状态变化，不只断言一句文本。沿用已有测试框架；下方小路由示例不是要求替换项目的对话插件。

## 最小路由实现与边界
[choice_routes.gd](choice_routes.gd) 只负责稳定 ID、无副作用过滤和提交时条件重验。过滤结果为空就返回 __return__ 路由；UI 根据 kind 退出或执行项目既定 fallback，而不是继续根据原始 options 是否为空判断。

路由不直接发奖励。把 choose 的成功结果传给已有事务层，在同一个同步提交边界复核业务条件并消费一次性动作 ID；多线程/异步场景不能把一次 UI 预检当成锁。不要在每次 redraw、进入一行或打字结束时重复结算。

测试至少区分逻辑层选择与 GUI 层事件：同一引擎 fixture 会过滤到零选项，再通过 Button 的鼠标事件返回；仍不等于操作系统真实设备测试。
