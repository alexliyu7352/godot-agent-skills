# 风险与证据覆盖

## 按变更选择，而不是按代码行数

| 变更 | 最小有意义证据 | 条件触发的扩展 |
|---|---|---|
| 文案/局部边距 | 相关界面的实际文本与布局 | 字体/Theme 公共资源变化时检查受影响界面 |
| 单系统规则 | 相关正常/错误分支及实际入口 | 公共 API/持久状态变化时增加关联回归 |
| 存档、时间、世界状态 | 不变量、迁移/恢复、跨系统玩家路径 | 涉及平台文件语义时进行该平台故障测试 |
| 场景结构 | 保存/重载、必需节点与初始化 | 输入/渲染变化时补真实交互/画面 |
| 性能修复 | 同条件采样与原行为复测 | 规模或长时间问题用对应压力/持续场景 |

已有项目明确要求优先执行。这里不强制所有任务 TDD、全量测试、独立审查、截图或录像；但选定的范围不能因为失败就临时缩小而不说明。

## 玩家路径示例
进入城镇 → 进入官署 → 与办事人员交谈 → 接任务 → 推进时间 → 返回交付 → 保存退出 → 重新启动恢复。

只取本次涉及的段落验证，不每次重跑全部。每段同时检查可操作性与权威状态：任务是否重复、奖励与消耗是否一起结算、时间是否正确推进、人物/场所引用是否保持、返回路径是否存在。

## 证据记录
记录命令或实际操作、工程版本/相关文件快照、环境与输入、退出结果、日志、图像来源、断言覆盖和未覆盖内容。复用证据时说明关联范围未改变；同名旧截图不代表当前版本有效。

自动工具只能证明它实际观察的范围。一次解析通过不是所有资源都加载；一次截图不是动画连续正常；一条成功日志不是状态正确；本地测试通过不是 GitHub CI 已运行。

## 失败后的迭代
保留失败证据；定位根因、修复并重跑受影响检查。不删断言、改成功标记或吞掉错误以“修复测试”。外部视觉审查有冲突时回到图像和标准核实，不因为多一个模型就自动否决或自动通过。

## 能力缺失
没有 Godot 可做静态审查，但不能写引擎测试通过；没有渲染/输入可做逻辑验证，但不能写交互/视觉通过；没有独立 agent 就不能声称完成独立评审。列出具体缺失项，不使用笼统“已全面测试”。
