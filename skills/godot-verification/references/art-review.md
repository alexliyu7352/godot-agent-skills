# 美术验收：看实际画面，不让技术证据越权

用于明确要求的视觉目标、重要场景或美术重设计审查。不是每次提交的全局门禁。先读取项目自己的品质目标；没有统一品味评分能证明所有游戏“好看”。

## 区分证据类型
| 证据 | 可以证明 | 不能自动证明 |
|---|---|---|
| 概念/合成图 | 构图、氛围、视觉候选 | 原生文字、可用图层、交互 |
| 独立资产预览 | 尺寸、alpha、轮廓与素材细节 | 与场景比例、光向一致 |
| 引擎截图 | 本次画面的真实呈现 | 点击路径、状态结算、长期玩法 |
| 输入轨迹与运行状态 | 操作到达、返回和状态一致性 | 美术风格获批、画面有趣 |
| 测试回归 | 指定条件没有已知错误 | 艺术质量、所有玩法正确 |

原始自动报告与后续看图记录分开，不回填机器日志为“已由人/模型看过”。截图绑定当前代码、资源和状态；旧图只能作为历史参考。

## 看图方法
先看完整画面，确认玩家视线落点和主要行动；再按实际尺寸看文字、人物和环境；最后放大检查相关边缘/材质问题。只查看本次改动影响的普通状态与关键边界，不为凑数量复制多分辨率同一图。

场景主导游戏可用三个诊断问题：去掉地点标题能否辨认场所职责？去掉功能面板还有没有人物和空间？关闭交互后是否仍身处同一地点？这些是诊断方法，不是禁止策略地图、菜单或极简游戏。

发现不一致时给出“位置—观察—影响—建议”，例如“右侧人物受光与窗户方向相反，像贴上去；优先修改素材光向”，不要只说缺质感。人物身份漂移、脸手遮挡、贴图裁切、输出中烧录假选项，都不能靠测试绿灯放行。

## 反例与判定
深色功能卡片加头像和一行地点名：技术可通过，但未满足在场交互目标。精美整屏合成图：视觉候选可能成立，但不能据此判原生 UI 通过。透明覆盖层：画面可相同，点击可能全部失败。静态绘景+真实热点：可判固定场景交互演示，不能宣称已做独立人物动作或日程呈现。

美术候选、用户批准、技术通过分别给状态；意见不一致时按项目目标说明差异，不用多个模型投票覆盖用户审美。不要把生成工具、仓库 Stars 或无错误日志当作品质裁判。
