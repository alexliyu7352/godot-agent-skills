# 设计与实现边界

初始日期：2026-10-02；边界澄清：2026-10-03。依据已确认的七入口合并精简方案实施。

## 目标
让开发 Agent 只发现经过筛选的 Godot 领域入口，保留专业知识和可执行的最小验证工具，减少原总控、重复路由和规则冲突。支持既有长期游戏工程，不改变玩法、语言、引擎版本或已经批准的流程。

## 结构
`skills/` 是唯一可安装内容源。七个 `SKILL.md` 分别拥有自身 `references/` 和必要 `scripts/`，没有跨技能强制依赖。来源页面只按审查需求读取，不发起自动下载。

`pack.json` 是显式发布清单并记录每个运行文件的 SHA-256；`sources.lock.json` 固定上游提交、路径和取舍。哈希用于发现差异，不是代码签名或远程信任机制。

`tools/install.py` 只把清单中的文件复制到一个明确项目的宿主技能目录；全量预检、受管文件收据、未修改检查和合作锁限制意外覆盖。常规异常尝试回滚；突然断电/kill -9 与恶意并发文件修改不在原子事务保证内。

`tools/validate.py` 检查发布边界、元数据、引用、来源、Python 注释与评估案例定义。`run_check.py` 使用真实子进程检查命令契约，完整输出留磁盘。无模型 API、安装器网络和付费服务。

## 能力与交付边界
技能可以指导游戏设计相关的工程决策、美术方向、现有工具辅助的资产生产/导入和实际呈现；这是知识层职责。具体玩法、风格和业务事实仍归用户项目文档，不写成所有游戏的硬规则。

不提供游戏生成器、MCP 服务器、资产生成服务、长期任务调度、模型路由、生产运维、角色工作室或新的规则框架。不附未经过引擎测试的大型对话/存档实现。示例仅用于揭示技能缺口或说明方法，不升级为另一款游戏的制作项目；官署案例不再构成发布前置任务。

现有工具与CI保持可用，除实际缺陷不扩建。内容审查优先核对具体上游方法、适用条件、冲突与在原工程中的接入方式，不以测试数量代替技能价值。[本轮内容审查](CONTENT_AUDIT.md)记录范围与取舍。

## 已执行路径
先定义打包与工具的失败用例，再写七个技能与参考；实现安装/验证工具，运行真实 Python 子进程及临时目录测试，做来源与引用审查，最后生成可恢复分发产物。

真实 Agent 基线/对照无法在当前环境执行，独立列为 NOT_RUN，不以静态测试替代。尚不能宣称触发准确率、游戏质量或开发效率提升幅度。
