# 合并、删除与纠错记录

## 合并不是压缩成通用口号
保留引擎特定决策、失败边界与验证方法；重复通用开发仪式和过度绝对规则删除。入口短，领域细节进入按需参考。源路径到目标技能的映射见 `sources.lock.json`；每个技能也附自身 sources 引用。

| 项目 | 处理 |
|---|---|
| awesome-gamedev 跨引擎路由 | 不发布，只有七个明确 Godot 入口 |
| GodotPrompter 总入口、完整 TDD/计划目录、角色配置 | 不发布，不与已有流程争夺控制权 |
| Godogen 完整生成、API 查询/视觉模型、发布脚本 | 不发布；只吸收场景/运行验证方法 |
| 两个或更多库中重复的验证口号 | 收敛为一个按风险选择证据的领域技能 |
| 示例 SaveManager/DialogueRunner | 不复制完整模板，改为明确契约和边界测试方法 |
| Resources 必须不含逻辑 | 不采用；依据所有权和生命周期选类型 |
| `%Name` 对目标重命名安全 | 更正为减少祖先路径依赖，仍使用目标名称与唯一作用域 |
| 共享资源内存修改自动写盘 | 不采用；共享状态污染与持久化分别处理 |
| 有选项但过滤后全空 | 明确 fallback/返回/结束，禁止继续判断只看原列表 |
| 未来存档只改版本标签 | 明确拒绝并保留原文件，迁移必须逐版本有语义 |
| pack 后节点数量相同就算正确 | 增加路径、类型、属性和磁盘重载验证 |
| headless 启动等于全项目/画面通过 | 分开导入、解析、逻辑、输入与渲染证据 |
| Input.action_press 等于真实点击 | 说明动作状态与事件路径的区别 |
| 工具退出 0 等于完整成功 | 捕获日志、完成契约和目标状态；保留工具能力限制 |

## 覆盖与剩余边界
面向 Godot 4 项目，但不声称所有小版本的 API 都已逐个运行；始终以工程锁定版本为准。C# 项目保持原语言与构建方法，本包不提供完整 C# 专题库。当前重点是场景、系统、UI、存档与质量，非多人网络、3D 渲染、XR 或所有类型游戏大全。

规则内容为本轮审读后的重组，不代表上游作者认可每项改写，也不表示上游后续版本仍有相同问题。具体引擎 API 参考官方文档，但任务中仍需按目标版本核实。

## 自动触发保证边界
包里物理上没有被淘汰的入口，因此本包本身不能注册它们。然而宿主的其他安装来源、此前已加载上下文和模型选择仍影响最终行为。窄描述与负例降低误触发风险，不构成零误触发证明；真实数据必须来自宿主运行记录。
