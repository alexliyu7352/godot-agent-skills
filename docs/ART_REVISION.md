# preview.3：从控件正确性补回游戏表现能力

## 本轮实际交付

仍然只有七个 Skill 入口。`godot-ui` 增加新画面、HUD、人物/背景家族和视觉重设计的适用条件；`godot-code-scenes` 增加场所分层和热点坐标；`godot-verification` 只在明确美术审查任务中评价表现质量。

五份按需参考已经进入发布白名单，不是留在仓库 docs 中的提案：

| 文件 | 具体方法 |
|---|---|
| `godot-ui/references/art-direction.md` | 主次、镜头、明暗、材质、字体的制作约束；用代表性画面定方向，不先铺功能卡片 |
| `godot-ui/references/asset-production.md` | 同一视觉种子的素材家族、alpha/锚点、源图与运行图、动态内容拆分、Godot 导入 |
| `godot-ui/references/game-presentation.md` | 进入—交谈—返回的同一场所；原生对白/选项；反馈、焦点和操作效率 |
| `godot-code-scenes/references/scene-composition.md` | 可选层级、人物与前景遮挡、cover/contain 的视觉与热点统一变换 |
| `godot-verification/references/art-review.md` | 概念/资产/引擎/操作证据分开；看完整画面和实际尺寸，给可定位的修改意见 |

固定来源 `awesome-gamedev@d4b0e35550c55ae70bdfcab4ef5a0e94610438a9` 的 `create-game-assets/SKILL.md` 与 `references/art-direction.md` 已阅读、重组并加入来源映射。Godot TextureRect/Control 的相关行为核对 4.6 官方文档；不要求使用者升级引擎。

## 没有改变的边界

修改一个间距仍然只处理局部，不触发重新设计、重新出图或全量视觉矩阵。没有新增总路由、Agent 角色、固定模型、收费 API 或图像服务凭据。具体《汉末行记》视觉设定留在 `examples/han-office/VISUAL_TARGET.md`，不强制所有游戏采用历史风格。

此前 15 张灰盒截图是技术反例，不是美术标杆，用户已否定其表现方向。本轮不改写历史记录，也不把它们重新称为“好看的游戏界面”。

## 验证与局限

新增三个分发测试先在旧内容上失败，补齐后通过；它们只验证参考能被安装/读取、来源映射存在、案例数与未运行状态一致，不评分美观或自动触发。

新增八个行为案例，累计 46 个：新官署、同角色素材家族、已定稿的局部间距、背景裁切与热点、烧录选项的概念图、明确美术审查、无关电商网页、只改商铺表现不扩经济系统。真实宿主结果仍为 `NOT_RUN`。

本地恢复环境是 preview.2 的 52 项基础测试，加入本轮三项后实际 55/55 通过；远端还有八项后续渲染/对照准备测试，因此完整远端预期 63 项，但以本次 CI 实际日志为准，不能把本地 55 写成远端 63 已通过。

## 概念图的当前判断

已重新查看上一轮会话中生成的官署主画面：房间、在场人物、光照和有限对白在构图上比灰盒接近目标；但那是带文字的单张合成 PNG，不是独立人物/前景资产，更不是运行截图。高桌式坐姿与视觉规格中的低案不一致；挂轴文字和陈设没有足够年代依据，不能称为汉末考古复原。

这张图可用作候选的构图与材质参考，不应整屏贴进引擎再覆盖透明按钮。下一步生产干净环境和可独立变化的人物/道具，再接原生文本、入口和返回。尚未完成这段制作，不以新增技能文档宣称美术成品已完成。
