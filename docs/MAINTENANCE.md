# 后续维护

维护一份规范化的 `skills/` 内容，不维护互相漂移的 Claude/Codex 正文，不保留原总控作为隐藏依赖。

## 修改步骤
先为涉及行为补测试或评估案例；修改对应入口或参考，必要时更新来源映射与取舍记录；更新运行文件清单哈希，再运行静态检查和 Python 测试。新增/删除入口是范围变化，本版固定七个，需重新审查触发边界，不能仅改 manifest 绕过限制。

更新清单使用 `python3 tools/update_manifest.py`。它只重算已列出的文件，不自动纳入新文件；新增文件须明确添加到 pack.json 清单后再运行。清单一致只能证明文件符合所列版本，不能自动证明内容合理。

## 上游更新
按 sources.lock 的 commit 对比具体差异，不自动合并新默认流程。保留有依据的方法，删除重复/不适用规则，修复被发现的错例。保留 Apache NOTICE 与 MIT 许可；不要把上游名称变成背书。

新资料先审查，不把完整上游检出放进本包的 skills/。不要添加所有主题的长教程来追求数量。只有现有入口确实缺少任务知识才补对应参考。

## 测试诚实性
静态、Python 子进程、真实 Godot、宿主触发、游戏端到端、视觉分别报告。GitHub workflow 文件存在不表示 CI 已执行。语义触发测试看实际调用记录，不能写一个关键词路由器然后用它给自己打分。

## 代码维护
所有项目自有具名类、函数、方法写用途/边界注释或 docstring。脚本使用 Python 标准库，明确副作用和错误退出，不引入 SDK、API key、下载器、模型路由或后台服务。
