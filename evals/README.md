# 真实 Agent 触发与使用评估

`cases.jsonl` 是 46 个预先定义的评估案例，不是 46 项已通过测试。preview.3 在原 38 个案例上增加八个美术/表现与局部范围案例。
`status.json` 当前明确记录 NOT_RUN。包结构测试、Python 子进程测试和作者审读不能替代这些行为评估。

## 评估范围必须分开

**技能选择**：固定宿主/模型/推理设置与目录上下文，让宿主正常发现七个入口，发送案例并查看真实调用/读取事件。不要提前告知预期技能名称，不在提示中直接引用 `$skill`/`/skill`；直接引用只测显式调用。

**参考发现与复用**：`prepare_agent_trial.py` 的五个工程由本包示例制造故障。安装包包含完整同名正确文件，复制回去可以直接恢复。它们可测参考使用和 helper 回归，不能单独测陌生工程泛化或净提效；评分器隔离不消除包内答案。细节见 [参考复用说明](HOST_TRIALS.md)。

**独立工程任务**：评价真实收益时，另选少量与本包示例结构不同、安装包不含整份答案的已有工程任务，固定独立验收，对照有/无包的完整结果。没有这种任务、轨迹和审查，就不报告未知工程成功率或效率提升。本轮没有新建此类任务或评测平台。

## 每次运行记录
保存 case ID、试验类别、运行时间、宿主和版本、模型/推理设置、起始源码、包版本/哈希、技能来源、调用与读取记录、diff、检查输出、人工干预及可用的费用/耗时。不得保存密钥。

每个条件至少重复 3 次观察波动，选型比较建议 5 次；用新上下文，交错顺序，不挑最顺利的一次。最初的单次 smoke 只用于确认运行路径，不用于估计稳定收益。

## 判定
`expected_primary_any` 是合理主技能候选，`allowed_pack_skills` 是允许扩展范围，不要求全部调用。negative 案例不调用本包正文。宿主通用技能单独记录，并检查是否启动已淘汰的 Godot 总控。

“只调对话框边距”只需相关 UI 方法，不因“对话”一词加载图/存档/完整验证。“未来版本存档”必须拒绝并保留原件，选对技能不是任务成功。对误/漏触发、重复读取、循环调用和流程扩张逐例核查上下文，不以字符串匹配正确率冒充技能质量。

## 状态与证据
长期检查验证关系，不把状态永久锁成 NOT_RUN。当前真实结果未变；未来采用 `NOT_RUN`、`PARTIAL`、`COMPLETED` 表示执行进度，不表示质量通过。

- 顶层 `cases_defined` 与实际案例数一致。所有宿主未运行时顶层为 NOT_RUN，两个结果指标保持 null，不引用运行证据。
- 有运行的每个宿主记录状态、非空 `version`/`model`，以及 `evidence` 文件列表；路径相对于本目录，指向保留在仓库中的非空报告/轨迹。报告说明任务类别、覆盖、推理设置、源码、结果与原日志位置，不能只写一句 passed。
- 只有部分声明的宿主执行时为 PARTIAL；COMPLETED 要与全部声明宿主一致。确实只评价一个宿主时可只声明该宿主，但不能据此宣传另一个宿主已验证。
- 有执行后指标仍可为 null；填入时为 0–1 数值，说明分母及试验类别。参考复用成绩不得混成未知工程收益。

CI 仅检查这些元数据和本地证据引用是否自洽，不能证明日志真实、任务有代表性或美术好看；更新结果前仍需实际运行和审查证据。单元测试中的合成完成记录只测试校验行为，不写入真实 `status.json`。不内置收费模型 runner、不改变模型默认值、不收集遥测。
