# 真实 Agent 触发与使用评估

`cases.jsonl` 是 46 个预先定义的评估案例，不是 46 项已通过测试。preview.3 在原 38 个案例上增加八个美术/表现与局部范围案例。
`status.json` 当前明确记录 NOT_RUN。包结构测试、Python 子进程测试和作者审读不能替代这些行为评估。

## 两层评估

第一层只测试技能选择：固定宿主/模型/推理设置与目录上下文，使用可复现的最小 Godot 工程副本；让宿主正常发现七个入口，发送一个案例，查看真实 Skill 调用或文件读取事件。不要提前告诉模型预期技能名称，也不要在用户提示中直接引用 `$skill`/`/skill`。直接引用只能测试显式调用。

第二层测试实际任务：使用能复现相应缺陷的工程 fixture 与独立验收规则，对比“无本包”和“有本包”的完整结果。不用本包自己生成的验收标准作为唯一裁判。没有这样的工程 fixture，本轮只能测选择，不能写功能成功率。

## 每次运行记录
保存 case ID、运行时间、宿主和版本、模型及推理设置、工程起始提交/变更快照、包版本/pack.json 哈希、全部技能来源、实际调用与读取记录、修改 diff、检查输出、人工干预和费用/耗时（可用时）。不要记录或分享密钥。

每个条件至少重复 3 次以观察波动；选型比较建议 5 次。使用新上下文，避免前一个案例已加载的技能污染下一个。测试顺序交错，任务难度保持一致，不挑一次最顺利结果。

## 判定
`expected_primary_any` 表示合理主技能候选，`allowed_pack_skills` 表示本例允许的本包扩展范围；它们不是要求一次全部调用。negative 案例不应调用任何本包正文。其他已有宿主通用技能单独记录，不把它们误算成本包越界；仍须检查它们是否激活被淘汰的 Godot 总控。

例“只调对话框边距”允许 `godot-ui`，不因“对话”一词加载对话图、存档或完整验证。例“未来版本存档”以拒绝和保留原件为正确行为，不能仅用选择了 save-load 判为任务成功。

记录误触发、漏触发、重复读取、循环调用和输出中有无被淘汰的流程指令。对每个自动匹配结果人工核查实际上下文，不能把字符串匹配正确率冒充技能质量。

本包不内置调用收费模型的 runner，不修改任何模型默认值，也不收集遥测。真实验证后应附可核查日志，再更新 status；不要把 NOT_RUN 手动改为 PASS 而没有证据。

实际工程 fixture 和无模型准备命令见 [夹具说明](fixtures/README.md)。引擎合同测试通过不改变本文件的真实宿主 NOT_RUN 状态。

工作区准备与可信验收见 [宿主对照操作说明](HOST_TRIALS.md)。渲染夹具与截图验收另见 [视觉说明](visual/README.md)。两者结果分别记录，不互相替代。

## preview.3 美术案例的范围
新增案例检查场景化意图、同一角色素材家族、保持局部改动、裁切与热点一致、概念图和原生 UI 的区别、明确美术审查及无关网页负例。它们只是预先给定的评估要求；没有声称已有完整艺术任务夹具或固定的美观评分器。
